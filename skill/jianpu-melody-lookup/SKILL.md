# 简谱旋律查歌

## 什么时候用

用户给你一段**旋律**（不是歌词、不是歌名），想知道是哪首歌。典型说法：

- "这是哪首歌：`5 5 5 3 2 2 3 5`"
- "哼一句查歌"、"识别这段旋律"、"帮我认认这个曲子"
- "下一句是 `3 2 1 1 6 1 2 6 5 5`，接的是哪首"

**不适用**：给歌名找谱、给歌词找歌（这个库里没有歌词）、识别五线谱图片。

## 怎么用

```bash
python lookup.py 51223323323531                    # 一段
python lookup.py "5 1 2 2 3 3 2 3 3 2 3 5 3 1"     # 带空格也行
python lookup.py 512233 6675 --top 5               # 多段一起查(分数相加, 更准)
python lookup.py 512233 --json                     # 给程序读
```

输入只认 `1`–`7`（简谱唱名）；`,6` 低八度、`'1` 高八度、其余字符忽略。**至少 5 个音**。

输出按"最小错音数"排序，每行给：错音数、**八度差异**、曲名、status、出处(`站点-id`)。

## 怎么解读结果（重要）

1. **看错音数**：0 = 完全命中；1–2 在长片段上仍很可能是对的；≥3 基本是乱猜。
2. **看八度差异**：主排序**故意忽略八度**（为了宽容哼唱），所以并列时看这一列。
   经典案例：《水手》与《爱上草原的小河》共享同一段 13 音，只差末两音的低八度
   （`,7 ,6` vs `7 6`）——错音都是 0，靠八度差异分开。
3. **并列就是"片段不够独特"**，不是工具坏了。换更长的片段、或补上中间那句，
   让"段段都接近"的歌胜出。多段查询就是干这个的。
4. **status**：`ok` = 人工校对过（可信度高）；`ocr` = 由图片机器转写（可能有辨认错误，
   错音数因此可能不为 0）。

## 指标（实测，不是宣称）

在 `train-work/mandopop_list.txt` 的**华流金曲清单**（319 首，库里能定位到其中 262 首）上，
每首歌取一段片段做查询，按**曲名**判定是否召回：

| 片段长度 | 哼错音 | Top-1 | Top-3 | Top-5 |
|---|---|---|---|---|
| 11 音 | 0 | **94.4%** | 98.8% | 99.4% |
| 11 音 | 1 | 69.4% | 88.8% | 93.1% |
| 15 音 | 0 | **98.1%** | 100% | 100% |
| 15 音 | 1 | 97.5% | 100% | 100% |

更严的口径（**留一版本**：把查询所用的那份谱从索引里删掉，只能靠"同一首歌的另一个版本"命中，
模拟"没有原谱、纯凭记忆"）：11 音 0 错时 Top-1 **41.2%**、15 音 48.8%（随机曲目抽样，
242 首多版本歌上测）；在金曲清单那个 21 首多版本子集上是 23.8%–42.9%。
两者差距说明：**片段检索的瓶颈是"片段是否唯一"，不是匹配算法**。

复现：`python eval_golden.py`（金曲口径）、`python eval_metric.py`（随机留一口径，口径说明见文件头）。

## 文件

| 文件 | 作用 |
|---|---|
| `lookup.py` | 查询入口，自包含（只依赖 `data.jsonl` + numpy） |
| `data.jsonl` | 数据集本体：7331 首（= HuggingFace `Caesium-132/chinese-jianpu-corpus`） |
| `eval_golden.py` | 金曲清单指标 |
| `eval_metric.py` | 随机留一指标（含两种口径的定义） |

换数据集：`--data 别的.jsonl` 或环境变量 `JIANPU_DATA`。

## 记法（数据里 `score` 字段的含义）

- 音高 `1`–`7`；`,` 降八度、`'` 升八度（可叠：`''1`）
- 时值前缀 `q`=八分 `s`=十六分 `d`=三十二分 `h`=六十四分；**无前缀 = 四分**
- `.` 附点、`-` 延长一拍、`0` 休止、`x` 念白、`~` 连音线、`3[ … ]` 三连音
- **本库不含歌词**：这是纯旋律语料，别拿歌词来查。
