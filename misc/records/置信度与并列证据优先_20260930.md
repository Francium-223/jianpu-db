# 2026-09-30：并列排序的问题 + 每个谱写 `confidence=`（转写置信度）

用户两句话促成这一篇：「并列排序有什么问题？」「所以每个谱转写后写一下 confidence=多少？」

## 一、并列排序的问题：**同代价时比的全是"与可信度无关"的量**

两边排序键都是 `(代价, …)`，问题在那个 `…`：

| | 原来的并列键（依次比） |
|---|---|
| 离线 `lookup.py` | 段落权 → **人气** → hot → 坏词 → 标题长度 → 曲名 |
| 前端 `search.js` | 记号数 → **人气** → hot → 段落权 → 坏词 → 标题长度 → 曲名 |

**这一串里没有一个在回答"这条谱可不可信"。** 于是实测翻车：

`33565653253` → 前端把《你怎么说》排第一（`ocr`，而且那条语料**本身就是转写误读** —— 见
`你怎么说那句是转写误读_20260929.md`），把《神々が恋した幻想郷》排第二（`ok`，**人工校对过**），
只因为前者人气/段落权更高。离线排对了**纯属碰巧**（它把段落权放在了人气前面）。

**影响面是量出来的**（`eval_golden.py` 新增"代价并列"一栏，按**曲名**去重）：

| 榜单 | L=11 错0：并列的查询 | L=15 错0 |
|---|---|---|
| 酷狗 2025 华流 | **15/87 = 17.2%**（并列时 Top-1 命中 8） | 6/87 = 6.9%（命中 3） |
| 中文流行 100 经典 | 18/116 = 15.5%（命中 11） | 7/116 = 6.0%（命中 6） |
| 金曲奖 30 年 30 首 | 7/30 = 23.3%（命中 3） | 2/30 = 6.7%（命中 2） |

⇒ 11 音那档**每 6 条查询就有 1 条是"好几首歌并列"**，而并列里谁能排第一基本对半开 ——
也就是说这批 Top-1 是**抽签抽出来的**。

**已改成"证据优先"**（两边同一口径）：

```
代价 → ① 人工校对过(ok) 优先 → ② 转写置信度高优先 → ③ 版本多优先
     → ④ 记号数 / 段落权 / 人气 / 坏词 / 标题长度（"更像你想找的那首"的偏好）
```

实测：`33565653253` **前端与离线现在都排《神々が恋した幻想郷》第一**；四榜指标没降
（酷狗 15 音 0 错 Top-1 **95.4% → 96.6%**，11 音持平 92.0%）。

## 二、`confidence=`：每个谱转完就写一个

**怎么算**：识别每个数字本来就是 `generate(do_sample=False)` 贪心解码 → 顺手要 `output_scores`，
取**每个数字首 token 的 top-1 概率**（真正决定"认得对不对"的就是它），平均成谱级 `confidence`；
另存 `conf_p10`（最低那 10% 的分位，用来看"有没有个别音很虚"）。

**开销是实测的零**（同一张图各跑两次、清空 crop 缓存）：关 **30.1s / 30.0s**，开 **30.0s / 30.4s**
—— 多要 `output_scores` 只是把已经算出来的 logits 做一次 softmax，不多跑前向。所以**默认打开**
（`JP_CONF=0` 可关）。

**落盘链路（一条口径，不散落）**：

```
jp_transcribe(概率) → batch-out/<name>.json 边车 → to_jianpu_db 写曲谱头 confidence=/conf_p10=
                    → parse_scores 进 data.jsonl（schema 里**登记**过这两条，否则会被 default_parse
                      切成 ["0.93"]，检索侧 float() 拿不到数）→ 前端卡片「置信度」一栏 + 并列排序第②顺位
```

老谱没有这个字段 → 卡片显示「—」（**不当 0.5 假数**），排序侧才用 0.5 当中性。

**它抓什么（实测，照实说）**：

| 谱 | confidence | conf_p10 |
|---|---|---|
| `夜曲 歌曲类 简谱__jianpucn-115143` | **0.76** | **0.42** ← 数字难认，该人工看 |
| `夜曲__jianpucn-35562` | 0.946 | 0.831 |
| 宁夏赋 / 宁夏好 / 学习雷锋好榜样 | 0.966 / 0.937 / 0.941 | 0.868 / 0.667 / 0.843 |
| 《你怎么说》那条**已知误读**页 | **0.964** | 0.903 |

⇒ **它量的是"数字认得清不清"，不是"这段旋律对不对"**。误读页照样 0.964 —— 错在**把行尾
`3 -` 和紧跟的括号连读**，不在单个数字认错，模型对自己读错的东西照样自信。所以两类错误两条闸门：

* **"虚"的谱**（模糊/低质扫描）→ `confidence` / `conf_p10` 低（如 0.76/0.42）
* **"结构错"的谱**（拼接假片段）→ 并列/独证提示 + 版本交叉核对 + 逐行重认定位

## 三、顺手修掉的一个**静默**坑

`to_score()` 读边车时原来写的是相对路径 `batch-out/…`，而转换器是被
`rebuild_when_idle.py` 用 **`cwd=tools/`** 调起来的 → 它去找 `tools/batch-out/…` → **找不到就静默
不写 `confidence=`**（不报错，只是这一栏永远空着）。改成按 `__file__` 推出仓库根拼绝对路径，
并实测：把 cwd 切到 `tools/` 再调 `to_score`，`confidence=0.946 / conf_p10=0.831` 正常写进头部。

**教训**：凡是从"另一个进程 + 另一个工作目录"里读文件，路径必须锚在 `__file__`，不能锚在 cwd。
