## 七、踩了一个**会自己把语料缩回去**的坑：只提交 `data.jsonl` 不够

`jianpu-db` 的 CI（`.github/workflows/parse.yaml`）是**从 `scores/` 重新生成 `data.jsonl` 再提交**的。
我这两轮只 `git add data.jsonl data.json by_*`，**忘了 `scores/`** ——
于是 CI 的 checkout 里根本没有那 1,227 个新曲谱，它每次自动重建都把 `data.jsonl` **退回 8,926 再推回来**；
本地 10,153 与远端 8,926 互相打脸，我 merge 一次就被覆盖回 8,926（一开始还误以为是"读到了重写中途的文件"）。

**修法**：`git add scores`（1,227 个：今晚导入的 813 + 白天导入的 414）+ 用本地 `scores/` 重跑
`parse_scores.py` → `data.jsonl` 回到 **10,153 首 / 音符 1,809,581**，推送（`47a7d3971`）。
之后 CI 的自动重建会得到同样的数。

**教训（写给自己）**：这个仓库的"数据"是**两件东西**——`scores/`（输入）与 `data.jsonl`/`data.json`
（产物）；**只提交产物 = 让 CI 用旧输入覆盖它**。以后入库后要么 `git add -A`，要么显式 `scores` + `data*`。

同一条也解释了另一个现象：`by_transcriber/…` 那些**符号链接**在 CI 里会变成"删除"（它的 checkout
生成不出同样的软链）—— 那些 delete 是 CI 自己造成的，不是丢了文件。
