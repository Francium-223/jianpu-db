# 「改编不收」口径的假阳性审计（2026-09-25，只读）

目标里有一条"改编口径"。这一轮只做了**只读审计**，结论是：**今天没有丢歌，但假阳性这一类是真的**。

## 一、口径是怎么判的

`queue_from_crawl.py:84`：

```python
arr = bool(ARRANGE.search(os.path.basename(d)))     # 目录名 = 站点标题
```

`ARRANGE`（`verify_crawl_matches.py`，两处共用一份）是**关键词正则**：

```
吉他|钢琴|古筝|竹笛|口琴|琵琶|二胡|小提琴|长笛|萨克斯|尤克里里|乐队|总谱|正谱|编配|
弹唱|和弦|指弹|独奏|伴奏|练习曲|考级|重奏|合奏|五线谱|简和谱|卡林巴|电子琴|双排键
```

命中即判"改编"，**改编不进转写队列**（语料口径：改编不收）。

## 二、假阳性长什么样

关键词出现在**歌名里**时就会误判。语料里**曲名本身**含这些词的共 **99 首**，我逐条看过：

| 类别 | 首数 | 例子 |
|---|---|---|
| 确实是器乐/教材类 | 56 | `C小调第五钢琴奏鸣曲 - Op.10`、`口琴七级：妈妈的吻`、`A大调钢琴五重奏 鳟鱼` |
| "曲名 + 乐器"式的改编谱 | ~36 | `暖暖钢琴`、`菊花台吉他`、`派对动物尤克里里谱`、`好汉歌 古筝版曲谱` |
| **歌名本身含乐器词的正经歌** | **7** | `又弹起心爱的土琵琶`、`二胡的故事`、`乡村吉他声`、`他的吉他`、`我的吉他两根弦`、`竹笛儿吹啊吹`、`琵琶曲` |

## 三、今天有没有丢歌？**没有**

那 99 首**都已经在语料里**（它们是更早的路径进来的，不走这条队列）。
而转写队列本身会**先排除"库里已有"**，所以这 99 首根本不会走到改编判定那一步。
**损失 = 0 首。**

## 四、但这类误判是真的会发生

一个反例就够说明：**《弹起我心爱的土琵琶》**（1956 年电影插曲）—— 歌名里带"琵琶"，
按现在的口径，将来从任何一个源爬回来都会被判成"改编"而**静默丢掉**。

我试着用正则把"歌名里的乐器词"和"描述性的乐器词"分开（比如要求关键词后面跟 `谱/版/曲`、
或在括号内），结果**分不干净**：`17岁钢琴简谱`（=《17岁》的钢琴版，确实该收成改编）
和 `又弹起心爱的土琵琶`（=正经歌）在字符串形状上是一样的。这一轮**没有改 `ARRANGE`** ——
乱改会把真改编放进来，代价比漏几首更大。

## 五、所以这一轮只留了一份"观察名单"

上面那 7 首写在下面，供以后核对（它们的 `file` 都在 `scores/`）：

```
又弹起心爱的土琵琶.txt   二胡的故事.txt   乡村吉他声.txt   他的吉他.txt
我的吉他两根弦.txt        竹笛儿吹啊吹.txt  琵琶曲.txt
```

**如果以后发现这几首（或同类歌名）被队列判成"改编"漏掉了**，那就说明该给 `ARRANGE`
加一条"歌名例外表"（白名单），而不是去动正则。
