## 为什么它能在库里:闸门漏了一类

流水线有"**念白 `x` 占比异常**"的闸(`quarantine_highx.py`:x>=30% 且 >=10 个 x -> 移出),
也有一条"旋律 < 5 个音"的闸(`quarantine_short_scores.py`)—— 但这些谱是 **9 个音**, 从两条缝里都漏过去了,
而**休止 `0` 没有任何闸**。

它们对检索不只是"没用", 还可能**有害**:9 个音的片段极短、极易与别的歌撞上(检索里
`L=7 音 0 错` 时并列组平均就有 39.6 首), 等于往索引里塞噪声。

## 与项目**已有**的质量审计的关系(没重做劳动)

我原来打算新写一个判据, 结果发现 `tools/audit_corpus_quality.py` **本来就有**一个等价信号:
它算 `ratio = 音符数 / token 数` —— "休止/延长占绝大多数"就是 **ratio 低**。真正的毛病在这一句:

```python
if n < 20:      # n = 有音高的音符数
    continue    # <- 用**音数**当门槛
```

**"音很少 + token 很多"的失败谱因此根本没被评估** —— 那 17 首里 16 首的 n_notes 只有 9~16,
全被这一句挡在门外(只有一首 n>=20 的进了 suspect)。改成**只在样本太短(token < 20)时跳过**,
音少的那一支只看 `ratio`(`top/n` 在 n 少时没意义)。

**效果(在同一份 8926 首语料上实测, 不受语料变化干扰)**:

```
新增评估 8 首:  junk 2 首(寻找莫扎特 n=5/tok=24、默 n=5/tok=30)
              suspect 6 首(再见理想_2 n=15/tok=52、大雪小雪又一年 n=14/tok=45、…)
```

两个信号的关系: 它是 **`n_pitches` / `top_pitch_ratio` 高 = 单调**, 我是 **ratio 低 = 空**;
在语料上它的 78 条 suspect 与我的 17 首**只重叠 1 首**(冬色)—— 所以是**互补, 不是重复**。
