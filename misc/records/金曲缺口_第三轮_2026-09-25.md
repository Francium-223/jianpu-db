# 金曲缺口：第三轮把 25 首"完全没图"的补到 12 首（2026-09-25 夜）

## 一、换了个入口：jianpujia 有可用的**站内搜索**

`crawl_jianpucn_by_title.py` 走的是"按字数分类逐页扫目录"，扫到 1400 页还没找到就没了
（上一轮 23 首只找到 5 首）。这一轮发现 **jianpujia 有能用的搜索**（EmpireCMS）：

```
POST https://www.jianpujia.com/e/search/index.php   show=title & keyboard=<曲名>
  -> 302 /e/search/result/?searchid=N ，页面里是 `/jianpu/<id>.html` + 标题
谱图在曲谱页里：https://image.jianpujia.com/jianpudq/jianpu40/<hash>.png  （一首 1~5 张）
```

（顺带：`/search.php`、`/so.php` 都是 404，只有 `/e/search/index.php` 这条通。）

新增 `tools/crawl_jianpujia_search.py`：按 `曲名@歌手` 搜 → 挑谱页 → 下谱图到
`images-prep/jianpujia-title/`。**不碰语料。**

## 三、这一轮自己踩的两个坑（都改了）

### 3.1 给了歌手却不匹配时，"退回全部前缀命中"→ 下错谱

第一版 `pick()` 在"给了歌手但没一个候选含它"时会**退回**所有"标题以目标开头"的候选。于是：

```
天籁@关正杰   -> 收下《天籁简谱_叶子演唱》     (不是关正杰的《天籁……星河传说》)
小三@丁禹兮   -> 收下《小三前传简谱_冷漠演唱》  (不同的歌)
哪吒@唐汉霄   -> 收下《哪吒动画片_哪吒传奇》   (不同的歌)
二十三@方大同 -> 收下《二十三号台风简谱》      (不同的歌)
```

**4 个错谱真被下下来了**。现在：给了歌手而无人匹配 → 只接受**标题完全相同**的候选，否则算没命中
（这 4 条改成"无命中"，会把候选打出来交人看）。已把这 4 个目录删掉，剩下的 11 个都逐一核对过。

### 3.2 先取到的是**钢琴谱**，而语料口径是"改编不收"

`queue_from_crawl.py` 会把目录名里带"钢琴/吉他…"的判成**改编**，而改编是**不进语料**的。
第一版按搜索原序取前 N 个，《最后一夜》先取到的是钢琴谱 —— 补回来也白补。
现在 `pick()` 里做**稳定排序：非改编在前**。重跑后《最后一夜》补到了 3 个**简谱**版本
（Live与KTV版 / 唱片完整版 / 简谱(歌词)），而不是只有钢琴谱。

## 四、顺带发现的两件事

* **缺口清单里的歌手/曲名有错**：`凄美地` 的歌手写的是"国定"，实际站点上是 **郭顶**；
  `绿叶对根的情义` 搜不到，正确的歌名应是 **《绿叶对根的情意》**（"意"不是"义"，但那首站点也没有）。
  这类错误会让"库里没有"的判定虚高 —— 缺口清单本身也该按页面标题校一遍。
* **140 个工具**里都硬编码着作者 Windows 的 `D:\Documents_D` 路径（`grep -rl 'Documents_D' tools/*.py`）。
  绝大多数是一次性脚本，但**维护中的爬虫也在其中**（这一轮修的 `crawl_jianpujia_category.py`
  同理）。冒烟清单现在只覆盖 33 个"当前维护"的工具，且"清单里有、文件却没了"会**明确报错**。
