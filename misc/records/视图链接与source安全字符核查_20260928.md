## 假警报 ①:`os.path.exists()` 判相对符号链接,**100% 报悬空**

第一版检查写的是:

```python
if os.path.islink(p) and not os.path.exists(p):   # <- 错
    dangling.append(...)
```

结果:`符号链接共 52926 个, 目标缺失 52926 个` —— **100%**。这个比例本身就是"尺子坏了"的信号。
拿一个具体链接验证:

```
os.readlink(p)   = ../../scores/th16_01.txt
os.path.realpath = D:\Documents_D\jianpu-db\scores\th16_01.txt   (存在 ✓)
os.path.exists(p) = False                                        (✗ 假)
PowerShell Test-Path -LiteralPath <链接> = True                   (✓)
```

**这台 Windows 上, `os.path.exists()` 对"相对目标"的符号链接会返回 False**, 而 `realpath` 正常。
判是否是悬空链接, 请用 `os.path.exists(os.path.realpath(p))`(或 PowerShell 的 `Test-Path`)。

## 假警报 ②:拿 by_title 的文件名去和 `scores/` 的文件名比, 报 14 处"对不上"

视图目录名/文件名用的是**清洗后的标题**(`score.py` 里对 `?` 等字符做过替换),
**不是** `scores/` 里的原始文件名 —— 所以"名字集合成员"这个测法本身就是错的。
正确的不变量只有一个: **链接能不能解析到真实存在的谱**(见上, 52926 个全好)。

> 教训与之前几次一样: **先怀疑尺子**。特别是"100% 全坏"或"整齐的差 N"这种结果 ——
> 它们几乎总是口径/API 语义的问题, 而不是数据真的全坏了。
