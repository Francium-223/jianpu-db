# 把"爬回来的新歌"变成语料：GPU 转写跑法（2026-09-25 夜）

**为什么要这份**: 覆盖的瓶颈不是算法而是"库里有没有这首歌"（L=15 时命中率取决于覆盖）。
今晚把爬虫批量跑起来后，**库外新歌有 5,375 首（其中非器乐改编、可转写 3,752 首）**，
只差**转写**这一步 —— 而本机转写不了（下面有实测原因）。这份手册让这件事在**任何一台有 GPU 的机器**上
一条命令接一条命令地跑完，不用再摸一遍。

## 一、队列从哪来（本机可跑，已跑）

```
python3 jianpu2/tools/queue_from_crawl.py --with-images \
        --out _analysis/转写队列_带图_20260925.tsv
```
扫的是工作区 `images-prep/` 里全部 316 个爬取来源目录，分拣口径与 `verify_crawl_matches.py` 同一份
（同一个 `ARRANGE` 正则 + `eval_golden.norm`）：

| 目录 | 库里已有 | 改编(不收) | 重复曲名 | **库外新歌(去重)** | **可转写(非改编)** |
|---|---|---|---|---|---|
| 20,346 | 12,869 | 2,069 | 2,102 | **5,375** | **3,752** |

TSV 列: `曲名 站 页面id 页数 类型 目录 首图`（`目录` 是 `images-prep/<来源>/<目录名>` 的最后一段，
用来找那一首的全部页图）。

## 二、转写 + 入库：`tools/batch_transcribe_queue.py`（今晚新写）

分两阶段，因为转写要 VLM（只能在 GPU 机上跑），入库只写文本（哪都能跑）：

```
# ① 转写（GPU 机）: 每页图 -> jianpu-ly token 文本 -> train-work/txq/<站>-<id>.txt
python3 tools/batch_transcribe_queue.py --stage transcribe --queue _analysis/转写队列_带图_20260925.tsv \
        --work train-work/txq --limit 20          # 先 20 首试速; 不加 --limit 就跑全部
# ② 入库（任意机器）: 产物文本 -> jianpu-db/scores/*.txt
python3 tools/batch_transcribe_queue.py --stage import --queue _analysis/转写队列_带图_20260925.tsv \
        --work train-work/txq
# ③ 重建索引（必须）
python3 jianpu-db/parse_scores.py
```
* 断点续跑: 已经入库的 `source=站-id`(现在 7,246 个) 会跳过; 转写产物已存在的那首也跳过。
* 每个入库文件都写 `transcriber=jianpu-vlm(v15)+crawl2026-09-25` 与 `status=ocr` —— **日后可按来源回溯质量**。
* `--dry-run` 只打印要执行的命令; `--only <字串>` / `--limit N` 便于小批试。
* **验证状态（诚实）**: `--stage import` 已用合成文本端到端验过（写出文件 → `parse_scores.py` →
  `data.jsonl` 里出现记录、音数 10/7 与元数据都对）；`--stage transcribe` 的命令拼装与找图路径
  用真队列 dry-run 验过（会打印 `transcribe.py <图> --out <页txt>`），但**VLM 那一步本机跑不了**，
  第一次真跑务必先 `--limit 2` 看一眼产物再放量。

## 三、GPU 机的环境（照着装就行）

```
pip install torch transformers peft bitsandbytes accelerate outlines
export HF_ENDPOINT=https://hf-mirror.com          # huggingface.co 在国内被污染
huggingface-cli download Qwen/Qwen2.5-VL-3B-Instruct --local-dir models/Qwen2.5-VL-3B-Instruct
python3 jianpu2/tools/check_transcribe_ready.py   # 要全 ✓ 才算就绪(它会逐项说缺什么、怎么补)
```
* 适配器/检测器**已经在仓库里**: `models/jianpu-lora-v15`(= jianpu-atom, 单音符 96–100%)、
  `models/grid_detect.pt`、`train-work/whitelist.txt`。
* 内存/显存: 4bit 3B 建议 ≥8GB; 本机只有 6.9GB 内存且**没有 GPU**, 所以跑不了。

## 四、跑完必须过的闸门（本机可跑）

```
python3 jianpu2/skills/jianpu-melody-lookup/selfcheck/selfcheck.py   # 语料不变量
bash jianpu2/tools/check_tools.sh                                    # 工具链 + 解析副作用
python3 jianpu2/tools/audit_corpus_quality.py                        # A 垃圾 / B 同源重复
python3 jianpu2/tools/coverage_gap.py                                 # 榜单覆盖率有没有涨
python3 jianpu2/tools/queue_from_crawl.py                            # 队列还剩多少(入库的会自动消失)
python3 jianpu-web/tools/refresh.sh                                  # 网页索引跟上(src 原文也从 scores/ 重读)
```
另外 `tools/check_images.py --queue` 是**送转写前验图**的老工具（短边过小/坏 PNG/HTML 错误页都能抓）。

## 五、别再走的两条死路（今晚实测，附数字）

| 路 | 为什么死 |
|---|---|
| 本机 VLM | 没 GPU；内存 6.9GB < 8GB；缺 7GB 基座与依赖 ⇒ `check_transcribe_ready.py` 判定"还跑不了" |
| 本机多任务 CNN | 用 1,355 个"图 + 库里已有转写"的同源样本量: 四个 checkpoint **相似度 0.00–0.04、前 20 音命中 26–50%**（盲猜 14%）= 随机。真实音符训练图 `train-work/real_notes_v4/` 已丢, 要复活得重造数据重训。门槛工具: `tools/check_cnn_accuracy.py` |
| 273 个 `status=midi` 的东方曲 dump | 是**多位转写者的分轨拼接**(每段 `%------…_人名.buf------` + `instrument=CH01`), 不是单旋律; MIDI 源文件不在仓库里(`jianpulocal/thmidi.py` 里只有当年的 Windows 清单)。而且全是东方曲, 对榜单覆盖没帮助 —— 收益低、风险高, 没做。 |
