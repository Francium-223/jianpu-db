# 语料不变量检查 2026-09-28（含一处真 bug 的修复）

## 为什么要写这个检查器

今晚抓到的几个问题**都不是"某首歌错了"**，而是**结构**问题：
`score.py` 的 Windows 反斜杠让首行被反复写脏、`by_*` 里长出垃圾目录、白名单漏字段导致整段音符消失。
这种"静默损坏"抽查几首歌是看不出来的，但用"每首都必须满足的等式"一眼就能看出来。
所以新增 `jianpu2/tools/check_corpus_invariants.py`（只读），检查 12 项结构不变量。

## 它抓到的第 1 件事：`bars` 里有**重复值**（已修）

```
检查 7318 首 → bars 不是严格递增: 3044 首; bars 越界(min=0): 239 首
例: 101.txt  bars = [1, 3, 6, 7, 7, 8, 8, 11, 15, 20]
```

**根因**（在 `jptok.recover_bars`，唯一实现里）：休止 `0` / 念白 `x` **占拍但不推进"第几个音"**
（`n` 只在有音高时 +1）。于是**一串休止跨过整小节**时，同一个音下标会被落两次线：

```
首 12 次落线(token, n, acc):
  ('0', 1, 4.0) ('x', 3, 4.5) ('x', 6, 4.0) ('x', 7, 4.0) ("x'", 7, 4.0) ("x'", 8, 4.5) ('0', 8, 4.0) …
                                              ^^^^^^^^^^ 同一个 n=7 落了两次
```
前端按 `bars` 插小节线 → **渲染出一个空小节**。

**修法**：`recover_bars` 出口去重（相邻重复只留一个）。
**注意保留开头的 `0`** —— 它表示"第一小节整小节是休止"，显示出来是有信息的。
（239 首 `min=0` 的因此**不动**。）

**影响面**：只动 `bars`/`data.jsonl`，**旋律一个音没变**。重建后 `git status` 只有 `data.jsonl`
（3044 行变化），`scores/` 零改动；自检门 9 条断言全过（含 `th10_06` 第一条线在第 3 个音之前）。

## 它抓到的第 2 件事：**音符碎片**（21 首 / 192 个，未修，需重转写）

```
score 里有音符碎片(可能丢音高): 21 首
   q~  97 个 · c~ 90 个 · s~ 4 个 · 1=C 1 个
   th07_13(24) th01_13(23) th01_12(16) th02_09(13) th02_03(12) th02_08(11) qd1z_anthem(10) …
```

`c~` 是"时值字母 + 连音线"，**没有音高**，而且它就夹在一串有音高的音之间：

```
th01_05.txt  … c'1 c- c- c- c~ q'1 q'1 q'2 q'3 …      ← c~ 那里很可能丢了一个音高
```

**自检门抓不到它**：那条断言是"数字数 == 旋律数"，而碎片里**没有数字**，两边都不算，
所以等式照样成立。这正是"同一个解析器自证"的盲区 —— 所以这个检查器用的是**独立判据**
（token 形状 + 结构记号白名单），不是再调一遍 jptok。

**影响**：约 192 个音高（占全库 1,300,814 个的 **0.015%**），集中在东方那批（thXX）。
**修不了（离线）**：音高信息在转写那一步就没了，只能对着原图重转写那 21 首。
清单：`py -3.13 tools/count_note_fragments.py`。

## 它抓到的第 3 件事：4 首 `source` 形状不对（未修，只是记着）

```
不潮不用花钱.txt unknown   相思遥.txt unknown   英雄.txt 21qupu   英雄_2.txt qpcxw
```
`unknown` 是占位符，`21qupu`/`qpcxw` 只写了站点名没写 id —— 这 4 首的"收录页"因此指不到具体页面。
不影响旋律与检索，属数据卫生问题；要修得有原页面 id（没有），或把它们标成"来源不明"。

## 检查器本身也修过两处"判据写错"（值得记）

* 把 `-`（延长）与 `~`（连音线）当成"解析不了的 token" → **6850 首误报**。它们本来就不是音符。
* `bars` 的下界写成 `1`，把"第一小节是休止"的 239 首误报成越界。语义上 `0` 是合法的。
> 教训同今晚其它几次：**判据写错时，报出来的"问题"会比真问题多得多**；先看样例再定结论。
