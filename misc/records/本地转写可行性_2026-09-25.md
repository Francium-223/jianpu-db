# 本机能不能"用本地模型转写"？—— 量过了：**不能**（2026-09-25 夜）

用户点名可以"用本地模型转写"。先把本机条件和两条路都实测了一遍，结论写在最前面：
**两条路今晚都不通**，但测量本身是有用的（下次别再重复试）：

| 路 | 卡在哪 | 实测 |
|---|---|---|
| VLM（jianpu-atom = `jianpu-lora-v15`，Qwen2.5-VL-3B） | 缺 7GB 基座（要下）+ 缺 torch/transformers 等依赖；**没 GPU**（核显 + Radeon）；内存 6.9GB < 4bit 3B 建议的 8GB | `check_transcribe_ready.py`：就绪 5 / 注意 2 / **缺 2**，结论"还跑不了" |
| 多任务 CNN（`models/multitask-v{1,1r,2,test}`，ResNet18 + 6 头） | 代码 `infer_multitask.py` **在抢救包里丢了**（全仓库只有 `transcribe_cnn.py` 里一句 import）；真实音符训练图 `train-work/real_notes_v4/` 也丢了 | 复原后实测（下详）：**不可用** |

## 一、先修好的两件事

1. **`tools/infer_multitask.py` 复原**（原来只有引用、没有实现）：模型结构直接 import
   `train_multitask.py` 的 `MultiHeadCNN`（不复制第二份），词表抄 `build_real_onehot.py`
   （`DIGITS=["1".."7","0","x"]`、`BEAMS=[0..4]`、`LOWS/VOICES=[0..3]`、`DOTS=[0,1]`、`ACCS=["","#","b"]`），
   token 组装走 `token_json.json_to_token`（唯一一份口径）。`load_state_dict(strict=True)`：键对不上当场炸。
2. **CPU 版 torch 装上了**（本机只有 Python 3.14，而 PyPI 的 Linux 轮子**硬要 CUDA 库**，
   `import torch` 直接 `libcudart.so.13: cannot open shared object file`）：
   用**上海交大镜像的纯 CPU 轮子**（带 sha256 可校验）：

       curl -sL -o torch.whl "https://mirror.sjtu.edu.cn/pytorch-wheels/cpu/torch-2.14.0%2Bcpu-cp314-cp314-manylinux_2_28_x86_64.whl"
       # torchvision 必须**配同一对**：0.29.0+cpu ↔ torch 2.14.0（装错会 RuntimeError: operator torchvision::nms does not exist）
       python3 -m venv .venv-cnn && .venv-cnn/bin/pip install --no-deps torch.whl torchvision.whl \
         && .venv-cnn/bin/pip install filelock typing-extensions sympy networkx jinja2 fsspec numpy pillow setuptools

   实测 `resnet18` CPU 前向 **热 22–26ms/图**（负载高时会到 13s/图 —— 是被别的进程抢占，不是 CPU 差）。

## 二、CNN 精度闸门：新工具 `tools/check_cnn_accuracy.py`

拿**同源样本**对照（同一首谱既有图、又有当年 VLM 转好的 `score`；按 `source=jianpujia-<id>`
**精确配对**，不靠曲名模糊匹配）——现有 1355 个这样的样本，这是最硬的对照集。

| 模型 | 相似度 | 前 20 音命中 | 判定 |
|---|---|---|---|
| multitask-v1 | 0.02 | 33% (n=4) | ✗ |
| multitask-v1r | 0.00 | 37% (n=4) | ✗ |
| multitask-v2 | 0.01–0.04 | 26–33% (n=8–10) | ✗ |
| multitask-test | 0.03 | 50% (n=4) | ✗（短样本蒙对） |

（7 个数字盲猜 14%。）**结论：这四个 CNN 在真实谱页上等于随机。** 这也解释了历史上为什么最后
走 VLM：CNN 是 9 月初的中间产物，`infer_multitask.py` 丢了之后没人再用它。
`check_cnn_accuracy.py` 现在把这个判定**变成可复跑的门槛**（前 20 音 <80% 就退非 0），
以后谁再训一版、或想接回这条路，先过这道门 —— 别拿它批量转写污染语料。

## 三、要复活本地转写，需要什么

* **最省事**：一张 ≥8GB 显存的 N 卡 + `models/Qwen2.5-VL-3B-Instruct` 基座（`hf-mirror.com` 下得动），
  用现成的 `transcribe.py`（当年 96–100% 单音符质量）。
* **纯 CPU**：得换小模型 + 量化（3B 在 6.9GB 内存上只能靠 swap，慢到不可用），
  或者**重新训一个 CNN** —— 但训练数据（真实音符图）已丢，得先用 `render_ly.py` 重造合成集
  再重新采真实图，成本远大于等一张 GPU。
* 无论哪条路：转写出来的谱必须带**独立的 `transcriber=`** 标注（现在的语料是 `jianpu2-auto` / 人工两种），
  便于日后按来源回溯质量。
