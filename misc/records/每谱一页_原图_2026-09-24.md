# 每谱一页 · 原图（2026-09-24）

> 用户：**"这个前端我还要加一个功能，每张谱都有一个单独的页面。显示它的原图。像 abcnotation 那个网站一样。"**
> 这一页就是 `/s/<id>`：左边是**扫描件原图**（多页就一页页堆下去），右边是全部元数据 + 收录页 +
> 补标签 + 原文（带小节线）。卡片上的标题和「本谱一页」片子都通到这里。

## 0. 一句话结论

原图**一直都在盘上**（`images/` 92MB + `images-prep/` 8.9GB，共 38,541 个图片文件），
只是在语料里没有名字能指到它。图片目录名是 `<抓取时的标题>__<source>`，而 `source`
正是语料的主键 —— 拿它当页面 id，**7,321 首里 7,281 首（99.5%）当场就有原图可看**，
一共 9,073 页。剩下 40 首（36 首没有 source + 2 首 `unknown` + 2 首没抓过图）页面上
**明说"还没存下原图"**，不留碎图。

## 1. 地址：`/s/<id>`

| 形式 | 谁在用 | 怎么工作 |
|---|---|---|
| `/s/qupu123-300587` | 本机服务（systemd，127.0.0.1:8770） | `app/server.py` 对 `/s/*` 直接返回同一个 `static/index.html`，前端按 id 渲 |
| `/#/s/qupu123-300587` | 纯静态托管（没有 SPA 回退） | 前端路由也认 hash 形式；文档路径仍是 `/`，相对路径不会错位 |

**id 怎么定**（口径只有一处：`jianpu-web/tools/build_web_data.py: tune_id()`）：
首选 `source`（本来就是全库主键、也是图片目录名 `…__<source>` 的后半截）；
没有 source / source 重复的退回 `f-<文件名去扩展名>`，重名挂 `-2`。前端**只按 id 查表**，
不重算 id。实测 7,321 个 id 全不重复。

### ⚠ 深链白屏那个坑（真浏览器才抓得到的），以及为什么用内联 `<base>`

`index.html` 里资产是相对路径 `<script src="./static/app.js">`（这是上一版**故意**的：为了能部署到
子目录 `user.github.io/jianpu-web/`）。但谱页地址是 `/s/<id>`，浏览器会把它解析成
`/s/static/app.js` → 404 → **整片白屏**，而假 DOM 的自检全绿。

改法见过两种，都不行：改成根绝对路径 `/static/…` → 子目录部署全废；在 HTML 里写死
`<base href="/jianpu-web/">` → 换个部署位置又要改 HTML。

现在的解法是 `index.html` **最前面**一段内联脚本（必须在 `<link>` 之前）：

```js
var p = location.pathname, m = /^(.*\/)s\/[^/]+\/?$/.exec(p);
var root = m ? m[1] : p.slice(0, p.lastIndexOf('/') + 1);   // 去掉末尾的 s/<id> 或文件名
document.head.insertBefore(base(root), document.head.firstChild);
```

于是：域名根 `/s/<id>` → 根 `/`；子目录 `/jianpu-web/s/<id>` → 根 `/jianpu-web/`；
首页 `/jianpu-web/` → 根 `/jianpu-web/`。**同一份 HTML 三种情况都对**，不用按部署位置改。
这一手靠 `browser_check.py subdir`（起一个带 SPA 回退的静态服务器，把仓库挂在 `/jianpu-web/`
子路径下打开）来证明。

## 2. 原图从哪来 / 选哪一份

```
images/<批次>/<标题>__<source>/001.jpg              最早几批的**原始下载件**
images-prep/<批次>/<标题>__<source>/001.jpg         处理过的**整页**（放大/去噪；后续抓取只有这一份）
images-prep/<批次>/<标题>__<source>/001_strip_MM.jpg  按谱表切的条（转写用，不是原图）
images-prep/<批次>/<标题>__<source>/001__pgN.jpg      站点多页/大图拆出来的派生件
song.json                                          抓取留档（site/id/title/page_url/images）
```

新工具 `jianpu-web/tools/build_image_index.py`（唯一一份扫描逻辑，`build_web_data.py` 调用它）：

1. **只把整页图当原图**：文件名是纯数字（`001.jpg`）；`_strip_`/`__pg` 不进原图列表，
   但一个目录**一张整页图都没有**时兜底（打 `drv` 标记，页面上写明"这是切好的条"）。
2. **太小的图丢掉（<100px）**：抓取时把站点广告条一起抓下来了 —— 实测某首谱的"第 1 页"是
   750×55 的横幅，显示出来是一条谁也看不懂的细条。丢了 **2,388 张**（11,461 → 9,073 页），
   但**没有一首歌因此变成没图**（都有真页）。
3. **同一个 source 有多个目录时排序**：有整页图 > 没有 → 整页图多 > 少 → `images-prep`
   （处理过、更清楚）> `images`（原始件）→ 路径。选中的那份之外，其余**当备选一起带出去**
   （`alt`，只存文件名不存尺寸），页面上给"另有：…（N 页）第1页 第2页"的小链接 ——
   用户要的是"原图"，处理件和未处理的原件都给他，由他挑。实测 2,086 个 source 有备选。
4. **坏图不进列表**（466 张读不动）：与其挂一个碎图图标，不如少一页。整页图全坏才退到下一个候选目录。

产物（每行一个 source，`data/images.jsonl(.gz)`，0.50MB gz / 3.1MB 明文）：

```json
{"s":"jianpucn-475740","d":"images-prep/ready3/我爱我们家__jianpucn-475740",
 "pg":[["001.jpg",1080,1919]],"drv":0,"alt":[["images/ready3/我爱我们家__jianpucn-475740",["001.jpg"]]],"nx":10}
```

带 `宽×高` 是为了**排版不抖**：页面直接写 `<img width height loading=lazy>`，图没到时位置也占住了。

## 4. 服务端（`app/server.py`）

```python
GET /s/<id>      -> static/index.html（前端路由；刷新/分享/直接打开都有效）
GET /img/<路径>  -> 原图（路径**相对工作区根**，如 images-prep/批次/标题__source/001.jpg）
```

* 根目录：`JIANPU_IMAGES`（冒号分隔）覆盖，默认工作区下的 `images/` 与 `images-prep/`
  —— 与 `build_image_index.py` 同一套默认。
* **三道闸**：百分号解码后逐段检查（不许 `..`、空段、反斜杠、NUL）→ 扩展名白名单
  （jpg/jpeg/png/gif/webp/bmp）→ 规范化后必须落在允许的根里面且是文件。越界一律 404。
* `Cache-Control: public, max-age=604800`（扫描件不会变）· 64KB 分块发（几 MB 的图不进内存）。
* 扫描件 8.9GB **不进 git、不进 HF 包**，就躺在工作区里由这个路由发。

## 5. 前端（`static/app.js`）

* 路由：`route()` 读 `location.pathname`（认 `/s/<id>`）→ 否则读 hash（`#/s/<id>`）→ 否则首页；
  `popstate` 重渲；应用内跳转用 `history.pushState`（**不整页刷新**，语料和检索结果都留着）。
* **应用根**从 `import.meta.url` 推（`new URL('../', …)`）：深链上 `./data/…` 会解析成
  `/s/data/…`，所以数据/图片/跳转一律以应用根为基准拼绝对 URL。
* 谱页版式（`body.tune-mode .wrap` 放宽到 78rem）：左栏原图 + 右栏元数据表 + 收录页片子 +
  补标签 + 反馈；下面「原谱原文」用 `renderScore(raw, null, 0, bars)` —— **只画小节线、不标黑**
  （整首谱没有"命中段"；`renderScore` 现在 `at=null` 就是这个模式，检索卡的标黑逻辑一行没动）。
* 卡片入口两处：**标题**变成通向谱页的链接 + 收录页那一行多一颗蓝片「本谱一页」。
* 没有原图的那首：页面上直说"这首还没存下原图（扫描件是按 source 归档的）"，并给出原谱站那一页；
  一首有多份扫描件的给备选链接；原文被截断（>400 token 的 2 首）会写明"只显示前 400 个 token"。

## 6. 顺手修掉的两笔旧账

1. **`data/songs.jsonl` 是个假明文**：它一直用 `gzip.open(..., compresslevel=0)` 写 —— 名字像明文、
   内容是 gzip 容器（头 `1f 8b`）。于是"老浏览器没有 `DecompressionStream` 时走这一份"的回退分支
   **从来读到的都是二进制乱码**，整个 app 直接"初始化失败"。现在是真明文（13.4MB，照旧入库）。
2. **补收录页/补标签现在立刻变绿**：以前保存成功后重跑渲染，但服务端重建索引要 ~2 分钟，
   所以"自动补充"其实要等两分钟才看得见。现在保存成功时**就地改浏览器里的索引**（检索结果与索引
   里那一首共用同一个数组对象）再重渲 —— 黄片立刻变绿；标签同理。`data-re="tune"` 让谱页也能原地重渲。

## 7. 怎么保证它不坏（5 层）

| 层 | 命令 | 管什么 |
|---|---|---|
| 假 DOM 渲谱页 | `node tools/check_tune.mjs` | 29 条：深链/标题/元数据/原图地址与宽高/编码/收录页/补标签/小节线数/没原图怎么说/不存在的 id/hash 形式/回首页 |
| 索引 vs 磁盘 | `python3 tools/check_images_index.py` | 索引里每条目录与页**真的存在** + 与 `stats.json` 对账（防"图片换了目录、用户看到碎图"） |
| 假 DOM 渲卡片 | `node tools/check_ui.mjs` `check_page.mjs` | 卡片上有「本谱一页」链接；标黑/小节线/收录页的老用例继续绿 |
| 真服务 HTTP | `node tools/check_live.mjs` | `/s/<id>` 能刷新、`/img/…` 真发出图片且带长缓存、**越界/非图一律挡住**（含 `%2e%2e`） |
| **真浏览器** | `python3 tools/browser_check.py spa` | geckodriver+firefox 无头：点了不刷新就跳过去、后退结果还在、深链刷新仍出图、`naturalWidth>0`（图真的解码了） |
| **子目录部署** | `python3 tools/browser_check.py subdir` | 临时起一个带 SPA 回退的静态服务器，把仓库挂在 `/jianpu-web/` 子路径下：路径深链、hash 深链、首页都要正常（验内联 `<base>`） |

以上前四层都在 `bash jianpu-web/tools/check_all.sh` 里（第 5 层检测到 geckodriver 才跑，没装就跳过）。
看某一页长什么样（不开浏览器）：`SHOW_TUNE=1 node tools/show_card.mjs 铺开一片蔚蓝 1`；
截图：`python3 tools/browser_check.py shot http://127.0.0.1:8770/s/qupu123-313063 /tmp/x.png --scroll 0,1500`。

## 8. 已知边界 / 下一步

* 40 首没原图（36 首没有 `source` 的早期谱 + 2 首 unknown + 2 首没抓过图）。要补只能靠抓取，
  不是前端问题 —— 页面上已明说。
* 图片只在本机由 `app/server.py` 发。**静态托管（Vercel/CF Pages/GH Pages）要先解决图片放哪**：
  要么对象存储/CDN（把 `stats.json` 的 `img_base` 指过去），要么把 `images/` 一并上传（8.9GB，不划算）。
  另外**纯静态主机没有 SPA 回退**，路径式深链 `/s/<id>` 会 404 —— 用 `#/s/<id>`（前端认，
  已用 `browser_check.py subdir` 验证），或给静态主机配 rewrite/404 兜底。
* 原图没有缩略图/分块：平均 230KB，直接发没问题；将来页面数多了再说。
* `.gitignore`：`images*` 不进 git；`data/images.jsonl.gz`（索引）跟着 web 仓库走，
  明文 `data/images.jsonl` 与 `songs.jsonl` 一样只在本地（服务端照发，老浏览器回退用）。
* 可做的下一步：① 从检索命中段跳到原图对应位置（要按小节坐标映射，工作量大）；
  ② 谱页上加"这一首的其它版本/同名曲"（现在要点回检索）；
  ③ 图片加 `?v=<mtime>` 防"换了图但浏览器缓存"。
