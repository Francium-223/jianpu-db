# 事故记录：用 `--help` 探测工具链**不是只读操作**（2026-09-28 凌晨）

## 一句话

`tools/check_tools.sh` 的做法是"对每个 `tools/*.py` 跑一次 `--help`，能 import 且打得出来就算过"。
今晚我在 Windows 上照这个思路写 `check_tools.ps1` 并跑了 `-All`，**触发了一批没有 `--help` 保护的工具
真跑起来**：空等一小时、改写 266 个草稿、开始加载模型重转写。

## 现场

| 工具 | 实际发生了什么 | 后果 |
|---|---|---|
| `autopilot.py` | 没有 argparse，`--help` 被当正常启动 → 进入 `wait_for_idle()`："等没有 python.exe 在跑" | 转写流水线**一直在跑**，于是它**空等一小时**，把整条冒烟自检卡死（后面的工具一个都没验到）。日志只有两行，没改任何东西 |
| `add_copyright.py` | 同上，真跑了一遍草稿后处理 | **改写 266 个 `scores-7b*/**.txt**：`copyright=歌谱简谱网` → `copyright=歌谱简谱网,版权归原作者及原网站`。这是该工具**本来的、幂等的**输出（它按 `scores-7b*` ↔ `images-prep/ready*` 映射补版权行），属正常结果 |
| `bench_batch.py` | 同上，开始**加载模型重转写**做吞吐测试 | 与转写流水线**抢 GPU**；被我及时杀掉，只留下 `train-work/bench_*.tsv/txt` 几个清单（未跟踪、可重生成） |
| `count_boundfix.py` / `bench_patch.py` / `bench_availability.py` / `bench_pick.py` | 只读统计，但会扫图 | 只写了自己那几份未跟踪清单 |

**受影响的跟踪文件只有那 266 个草稿**（都是 `add_copyright.py` 的正当输出，已保留并提交）；
其余都在 `train-work/`、`train-data-atoms-v4-json/` 这些**未跟踪**目录里，随时可重生成。

## 根因

**"用 `--help` 探测"这个动作本身就假设了工具会解析参数。** 实测：

```
tools/*.py 里没有 argparse、也没有 `--help` 守卫的：494 个
```

也就是说 —— 项目自带的 `check_tools.sh` 只要跑一次，就有 494 个工具**会被真正启动**。
过去没出事，只是因为那份 `TOOLS=...` 手写清单里恰好都是带 argparse 的（而且 09-25 的记录里
已经因为"清单是手写的"烂过两个口子）。`autopilot.py` 这次是被我的 `-All` 才第一次这样调用到。

同一个坑 09-25 已经踩过一次小的：`mbid_lookup.py` 没有 argparse，`--help` 被当曲名，
**真去 MusicBrainz 查了一次 "--help"**（返回一堆 Harry Potter）—— 那次只是白打一次 API。

## 修法（都已在 `jianpu2`）

1. **`check_tools.ps1` 改成按设计不可能有副作用**：
   * 第一步永远做**静态**语法检查（`ast.parse`）——零副作用；
   * 第二步**只对源码里出现 `argparse` 或 `--help` 字样的工具**真的执行 `--help`；
   * 其余**跳过并打印名单**（说清为什么跳过）；
   * 每个工具带 **25 秒超时**（超时算失败）——防止再有工具不认 `--help` 把整条卡住。
   现在的结果：`语法 OK 且 --help 正常 34 / 检查 40; 跳过 6`。
2. **`autopilot.py` 补 `--help` 守卫**（与 `mbid_lookup.py` 同款）：`--help` 立刻打用法退出。
3. 新增 **`tools/list_unguarded_tools.py`**：列出那 494 个没有守卫的工具，并粗判哪些"有副作用风险"
   （含 `open(`/`subprocess`/`urlopen`/`Image`/`torch`）。要不要给它们补守卫，看这份名单再决定。

## 教训（写进"照着躲"清单）

* **探测工具不要用会触发业务的参数**。要验"能不能 import"，静态解析永远安全；要验运行时，
  就得先确认那个工具**声明了**只读入口（argparse/`--help`/`--dry`）。
* **批量脚本一定要带超时**。一个不认参数的工具有可能不是"报错退出"，而是"开始干活并永远等下去"。
* **杀掉命令行里带某关键字的进程时，要先按 `Name` 收窄**。我第一版按 `CommandLine -match 'autopilot'`
  杀，结果把**我自己那条命令行**（里面也含这个词）一起杀了，把 DSH 的 job runner 搞崩了一次。
