# 曲名病灶：尾部悬挂分隔符（40 首，2026-09-25）

## 现场

语料里有 40 首的 `title=` 尾部挂着一个没有内容的分隔符：

```
title=可惜没如果 —          title=塞纳河——            title=托起梦中的太阳·
title=星光 —               title=菊花台吉他 —          title=春の氷精　- 静 -
title=Castle Explorer -in the Sky-
```

来源：早前某版解析把歌手拼进过曲名（`曲名 — 歌手`），后来不拼了，只剩个分隔符尾巴。

## 判据（不猜，可复核）

**全库 7,318 首里 `title` 含 `" — "` 的只有 1 首。** 也就是说本站曲名约定就是"只有曲名"，
歌手另有 `artist=` 字段（这 40 首里 13 首有 artist、27 首没有）。

→ 所以正确修法是**把尾巴去掉**，而不是把歌手补进去。这一点我一开始想反了：
看到 `可惜没如果 — 林俊杰` 的 `artist=` 就以为约定是 `曲名 — 歌手`，
先数了一下才知道全库只有 1 首那样写 —— 数完才动手。

## 做法

复用 `refine_titles_from_pages.py` 新增的 `--strip-dangling`：

* 判据就是曲名自身的形状：`^(?P<core>.*?)[\s\u3000]*(?:—+|–|--|-|·|_)[\s\u3000]*$`，
  去掉后必须还剩东西（否则 `title=—` 会被抹空）；
* 全离线（不需要页面标题），所以**不受**该工具"跳过 jianpucn"的限制 —— 这 40 首里大部分正是 jianpucn；
* 改名沿用原有冲突规则：`曲名.txt` → 撞名则 `曲名（歌手）.txt` → 再撞 `曲名（歌手）_2.txt` → `曲名_2.txt`。
  `pick_target()` 的 `free()` 会查 `os.path.exists`，不会覆盖任何现有文件。

结果：**40 首全部改名 + 去尾巴**，`grep -E '^title=.*[—–·_-][ 　]*$' scores/` 从 40 → **0**。

## 踩到的坑（记下来，因为很隐蔽）

第一次 `--apply` 之后，我核对"只该改 `title=` 一行"时发现：**首行 `%<本文件名>` 也带旧文件名**，
而它没被改：

```
%可惜没如果_—.txt          ← 文件名已经叫 可惜没如果.txt 了
title=可惜没如果
```

这不是"难看一点"——`score.py` 里明确拿它做判断：

```python
if i.startswith('%'):
    if i != '%' + self.score.split('/')[-1]:   # `%<本文件名>` 只是自述, 不进 comments
        self.comments.append(i.rstrip('\n'))   # ← 不相等就**当普通注释收下**
```

于是这 40 首会凭空多出一条"旧文件名"注释。而且我第一次修还修错了：写成 `"%" + fn[:-4]`，
**但这一行是带扩展名的**（`%可惜没如果_—.txt`，score.py 比的就是 `'%' + 完整文件名`），
所以第一次修完检查仍是 40 处不一致。

处理方式：`git checkout -- scores/` + `git clean -fd -- scores/` 完全还原 → 改对工具 → 重新 `--apply`。
最终核对（脚本逐份比对 HEAD 里的旧文件与新文件）：

```
改名 40 份: 除首行/title/todo 外**逐字节相同** = 40 份, 异常 0
首行 %<名> 与文件名不一致: 0 （全库 7,816 份）
data.jsonl 未被触碰
```

（`todo=refine the filename` 那行被清成空行，与工具原有行为一致 —— score.py 里空行本来就被跳过。）

## 没做 / 留给下一轮

* **1 字曲名（63 首）**：多数是**真的**单字歌名（`嗯`/`妳`/`念`/`望`/`渡`/`烧`…，页面标题能佐证），
  但至少 `丽`（页面是《美丽的草原》）、`家`（页面是《家在草原根在草原》）、`岁`（页面是《17岁（十七岁）》）
  是被截断的。这批**动不了离线判据**（要判断"这个单字是不是完整歌名"必须看页面），
  且 jianpucn 的页面标题本身很脏（`美丽的草原童童词张文曲美丽的草原童童词_张文曲简谱-`，重复两遍），
  所以没有动，留作下一轮：要么人工过一遍，要么先做页面标题的去噪。
* **`source_pages.json` 的 `via` 语义**（上一轮记的）：jianpucn/jianpujia 的候选 URL 是**按 id 拼**的，
  所以那里的 `via:id` 是循环论证（100 条无独立证据）。要改得先写独立文件再 diff，避免丢数据。

## 复现

```bash
cd jianpu2
python3 tools/refine_titles_from_pages.py --strip-dangling --plan     # 只打印计划
python3 tools/refine_titles_from_pages.py --strip-dangling --apply    # 落地
grep -rlE '^title=.*[—–·_-][ 　]*$' ../jianpu-db/scores/ | wc -l      # 应为 0
```
